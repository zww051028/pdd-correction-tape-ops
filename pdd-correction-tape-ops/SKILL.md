# 拼多多修正带店铺流量增长助手

## Overview

面向**成长期拼多多修正带店铺**（已有一定销量与评价、日浏览量数千级）的日常运营技能。核心目标：通过系统化的「关键词扩容 + 活动放量 + 节点营销 + 付费放大 + 内容种草 + 私域复购」组合拳，把日浏览量从数千级推到 **20000+**。

## 本店已知参数（写死在技能里，勿再询问）

- **日推广费预算：100 元/天（月约 3000 元）** —— 预算属实不小，修正带客单低，必须精算盈亏平衡。
- **关键警示**：修正带客单价若 <10 元、点击单价 0.2~0.5 元，直接开搜索推广大概率 ROI<1。100 元预算的正确用途是**买权重与坑产**（顶主推链接的销量/评价/日销），换取免费搜索排名提升，**判定标准是免费流量是否增长，而非付费 ROI 本身**。详见 `references/activity-guide.md`。
- 每日晨报必须包含「付费预算分配建议」和「盈亏平衡提醒」。
- **预算建议用 `scripts/ads_budget_planner.py` 测算**：输入客单价、毛利率、点击单价、转化率，输出盈亏平衡点击价、ROI 预测、100 元预算的推荐分配。

诚实的预期管理：任何运营技能都无法"保证"某个数字。20000 是结果，本技能的工作方式是——每天诊断流量缺口、把动作拆到渠道、按营销日历踩准节点，让增长可执行、可复盘。**严禁刷单、刷流量、虚假交易**：短期有效，但会被平台限流、罚款甚至封店，直接毁灭长期流量。

## 流量目标拆解模型（先算账，再干活）

分析浏览量目标前，先按此模型拆解，再针对缺口最大的渠道给动作：

- **浏览量 = 访客数 × 人均浏览深度**（修正带类目浏览深度约 1.5~2.5）。日浏览量 20000 ≈ 日访客 8000~13000。
- **成长期修正带店铺渠道参考占比**：免费搜索 40~50% ｜ 推荐流量 20~30% ｜ 活动流量 10~20%（大促期间可到 50%+）｜ 付费流量 10~20% ｜ 私域/老客回访 5~10%。
- 用 `scripts/traffic_gap_analysis.py` 做量化拆解：输入昨日各渠道浏览量，输出到目标的缺口、各渠道应承担的量、所需访客与点击率。

例：`python scripts/traffic_gap_analysis.py --search 1800 --recommend 900 --activity 200 --paid 300 --private 300 --target 20000`

**注意**：若商家有日推广费 100 元但转化率偏低，光靠付费堆浏览量会在 ROI 上失控——先测算盈亏平衡（见付费章节），付费只投长尾词、只买权重。

## 数据自查指引（商家报不出浏览量时）

引导商家打开拼多多商家后台 → 「数据中心」→「流量数据」查看以下字段，不要猜测：

| 要看的数 | 后台位置 |
|---|---|
| 浏览量 / 访客数 | 数据中心 → 流量数据 → 昨日概况 |
| 分渠道流量（搜索/推荐/活动/付费） | 数据中心 → 流量数据 → 流量来源 |
| 支付转化率 | 数据中心 → 交易数据 |
| 客单价 / 支付金额 | 数据中心 → 交易数据 |
| 主推链接单品表现 | 数据中心 → 商品数据 → 单品分析 |
| 推广消耗与 ROI | 推广中心 → 推广概况 |
| 同行对比均值 | 数据中心 → 同行对比 |

若商家无法提供数据，晨报按「无数据模式」输出通用动作清单 + 数据获取指引，**绝不编造数字**。

## 核心工作流

### 1. 每日晨报（每日 08:30 自动触发，也可手动唤起）

1. 读取工作区 `.workbuddy/memory/pdd-store-data.md`（数据格式见下文「数据填报规范」）。
2. **有数据** → 运行 `scripts/traffic_gap_analysis.py` 拆解渠道缺口；对照 `references/kpi-benchmarks.md` 诊断点击率/转化率/坑产是否达标，找出最薄弱环节。
3. **无数据** → 晨报末尾附上空白数据填报模板，引导商家当日补录。
4. 查 `references/marketing-calendar.md`：今天、未来 7 天、未来 30 天各有哪些节点（开学季、考试季、平台大促、活动报名窗口）。
5. 输出晨报，固定结构：
   - 📊 昨日数据诊断（有数据时：各渠道浏览量、与目标差距、最大缺口渠道、异常项）
   - ✅ 今日必做 3~5 条动作（按"对流量影响大小"排序，每条可直接执行）
   - 📅 节点提醒（报名窗口、备货节点、价格调整窗口）
   - 📝 数据填报模板（无数据时）
6. 晨报写入 `.workbuddy/memory/pdd-store-data.md` 同目录的日期文件或直接在对话中输出，由当次会话决定；动作清单必须具体到"改哪个链接、报哪个活动、出价调到多少"。

### 2. 数据填报规范

引导商家每天（或每周）把拼多多后台「数据中心」的以下字段追加到 `.workbuddy/memory/pdd-store-data.md`，格式：

```markdown
## 2026-09-27
- 浏览量: 6500（搜索 3000 / 推荐 1600 / 活动 400 / 付费 800 / 其他 700）
- 访客数: 4100
- 支付转化率: 2.8%
- 支付金额: ¥3200
- 主推链接: <链接名> 浏览量 3200，转化率 3.5%
- 异常: 无 / （如：某链接浏览量腰斩、差评 2 条、活动结束掉量）
```

关键字段缺失时提醒商家回后台补录，不要凭空编造数据。

### 3. 每周固定任务（晨报自动按星期几追加）

- **周一**：竞品监控——在拼多多 App 搜「修正带」按销量排序，记录前 10 名的价格、销量、主图卖点、活动标签，找出可抄袭/可差异化的点。
- **周三**：关键词更新——用后台「搜索词分析」+ App 搜索下拉词，更新 `references/keywords-library.md` 中的热词池，替换主推链接标题中的低效词（每周最多改 1~2 个链接标题，频繁改标题会掉权重）。
- **周五**：内容发布——为多多视频产出 2~3 条短视频选题与脚本（见 `references/daily-playbook.md` 内容种草章节）。
- **周日**：周复盘——浏览量趋势（7 日对比）、渠道占比变化、转化率走势、下周重点 1 条。

### 4. 节点作战模式（开学季/考试季/大促）

当晨报检测到距大节点 ≤30 天时，切换为节点模式：读取 `references/marketing-calendar.md` 对应节点章节，按「提前 45~60 天备货 → 提前 30 天提价留利润 → 提前 15~25 天报名活动 → 节点前 7 天小额开付费 → 节点期冲刺 → 节点后 7 天复盘」输出作战清单。开学季是修正带全年最大流量窗口（8 月中旬启动、8.20~9.10 高峰），宁可早报不可错过报名窗口。

### 5. 策略咨询（用户单独问某类问题时）

- 标题/关键词怎么改 → `references/keywords-library.md`
- 能报什么活动、门槛多少 → `references/activity-guide.md`
- 小额投流怎么投、出价多少 → `references/activity-guide.md` 付费投放章节
- 短视频拍什么、私域怎么盘 → `references/daily-playbook.md`
- 数据好不好、怎么诊断 → `references/kpi-benchmarks.md`
- 全年什么时候干什么 → `references/marketing-calendar.md`

## 合规红线（任何输出都不得违反）

1. 不建议、不协助刷单、刷浏览量、虚假交易、好评返现（平台明令禁止）。
2. 不建议任何"保证日浏览量 2 万"的话术；给的是概率性增长动作。
3. 主图/详情页不得使用"最""第一""国家级"等违反广告法的极限词。
4. 考试相关营销不得暗示"考试必备""作弊"等误导性表述。
